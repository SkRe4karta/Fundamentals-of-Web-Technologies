# Food Construct — лабораторная работа №8

Продолжение ЛР №7.

## Что реализовано

- выбранные блюда сохраняются в `localStorage`; хранятся только их числовые ID;
- после обновления `lunch.html` выбранные блюда восстанавливаются;
- добавлена страница `order.html` («Оформить заказ»);
- состав заказа на `order.html` загружается из `localStorage`, а данные блюд — из API;
- на карточках заказа кнопка «Удалить» удаляет ID из `localStorage` и пересчитывает стоимость;
- форма оформления заказа перенесена на `order.html`;
- перед отправкой проверяется допустимое комбо из ЛР №6;
- на `lunch.html` вместо формы сделана `position: sticky` панель с текущей стоимостью и ссылкой на оформление;
- ссылка на оформление недоступна, пока состав не образует допустимое комбо;
- заказ отправляется через `fetch()` методом POST на `/orders`;
- при успешном POST выбранные блюда удаляются из `localStorage`; при ошибке остаются;
- подписи фильтров сохранены с заглавной буквы.

## ВАЖНО: API key

Откройте `config.js` и вставьте персональный ключ из СДО:

```js
const API_KEY = "ВАШ-КЛЮЧ";
```

Ключ индивидуальный, поэтому в готовый архив он намеренно не включён.

## Запуск

Откройте проект через Live Server. Основная страница выбора — `lunch.html`, страница оформления — `order.html`.

Эта версия строго использует API для меню и оформления заказа. Если учебный сервер отвечает 502, используйте отдельную offline/fallback-версию для демонстрации интерфейса.
